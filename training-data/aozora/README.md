# 青空文庫コーパス（小説スタイル用ファインチューニング素材）

「小説」スタイルのモデルをファインチューニングするための青空文庫収録作品コーパス。

## 収録作品・著作権について

[青空文庫の公式メタデータCSV](https://www.aozora.gr.jp/index_pages/list_person_all_extended_utf8.zip)（`list_person_all_extended_utf8.csv`）の「作品著作権フラグ」列で`なし`（＝著作権保護期間満了、公開可）と確認された作品のみを採用。

| 作者 | 作品数 | 没年 |
| --- | --- | --- |
| 夏目漱石 | 3 | 1916年 |
| 芥川竜之介 | 5 | 1927年 |
| 太宰治 | 3 | 1948年 |

収録作品:
- 夏目漱石: こころ／坊っちゃん／吾輩は猫である
- 芥川竜之介: 蜘蛛の糸／杜子春／鼻／藪の中／羅生門
- 太宰治: 斜陽／人間失格／走れメロス

## 出典・抽出方法

各作品の[XHTML/HTMLファイル](https://www.aozora.gr.jp/)（Shift_JIS）を取得し、以下の変換でプレーンテキスト化:
- `<div class="main_text">`〜`<div class="bibliographical_information">`の区間のみ抽出（本文以外の書誌情報・入力者クレジット・表記についての注記は除外）
- `<ruby><rb>漢字</rb>...</ruby>` → `漢字`（ルビ本体のみ残し、読み仮名は破棄）
- 章見出し（`<div class="jisage_*">`配下の`<h4 class="naka-midashi">`）は除外
- `［＃…］`形式の入力者注記を除去
- 残りのHTMLタグを除去、`<br />`は改行に変換

各作品の出典URLは`corpus.json`の`url`フィールドに記録済み。

## ファイル

- `corpus.json` — `{author, title, url, text}` の配列（出典追跡・クレジット表記用）
- `corpus.txt` — 本文のみを連結したプレーンテキスト（学習入力用、作品ごとに空行区切り）

## 規模

11作品・合計約231万文字（約2.3MB、トークン数で約47万）。童謡コーパス（[training-data/douyou/](../douyou/)、約8,800文字/6,600トークン）と比べて約71倍（トークン数ベース）大きく、ファインチューニング時の過学習リスクは低い見込み。

## ファインチューニング結果（2026-07-31実施）

- 学習: 走れメロス・藪の中の2作品を検証用に残りの9作品で学習（BLOCK_SIZE=512でチャンク化、作品間はEOSで区切り）、5epoch
- **採用: epoch3**（検証ロス最小）

### わかったこと

- **童謡コーパスと違い、検証ロスが安定していた**: epoch1=4.160→epoch3=4.141(最小)→epoch5=4.144と、振れ幅0.02程度のほぼフラットな推移。童謡コーパス（epoch5=3.72→epoch40=4.39と大きく悪化）のような激しい過学習カーブは発生せず、ロス最小のepochをそのまま採用してよい結果だった。コーパスサイズがモデル規模に対して十分大きければ、検証ロスによる選定は素直に機能する
- **生成文の質感も良好**: 「〜けれども」「〜だそうだが」等の文語調接続、「」による会話文、「お嬢さま」「君」「おれ」等の古風な人称など、明確に文体が変化した。童謡コーパスで見られた「馬にゃんこ」のような意味崩壊は見られなかった
- **重要な副産物の発見**: アプリの実際の生成プロンプトには単語だけでなく「◯◯、◯◯、◯◯を使った文章を作ります。」という前置き文（`intro`）も含まれていたが、これは学習コーパスに一切登場しないパターンだったため、この前置き込みでは文体変化が大きく薄まってしまうことが判明（量子化の影響ではなく、生のPyTorchモデルでも再現）。`src/App.tsx`側で修正し、モデルへの実プロンプトからは`intro`を除外（UI表示用としては残す）。これは詩・小説どちらの文体にも影響する問題だった
