# 童謡コーパス（詩スタイル用ファインチューニング素材）

「詩」スタイルのモデルをファインチューニングするための童謡歌詞コーパス。

## 収録作詞者・著作権について

歌詞テキストのみを学習に使うため、著作権の可否は**作詞者の没年**のみで判断（作曲者は無関係）。
2018年の法改正で保護期間は没後70年（2026年時点で1956年以前に没した作詞者が対象）。

| 作詞者 | 没年 | 収録曲数 |
| --- | --- | --- |
| 野口雨情 | 1945年 | 13 |
| 北原白秋 | 1942年 | 23 |
| 高野辰之 | 1947年 | 6 |
| 清水かつら | 1951年 | 5 |

4人とも没後70年超で、いずれもWeb検索で没年を確認済み。

## 出典

歌詞本文は [worldfolksong.com](https://www.worldfolksong.com/songbook/japan/index.html)（世界の民謡・童謡）の各曲個別ページからスクレイピング。
各曲の出典URLは `corpus.json` の `url` フィールドに記録済み。

## ファイル

- `corpus.json` — `{author, title, url, lyrics}` の配列（出典追跡・クレジット表記用）
- `corpus.txt` — 歌詞本文のみを連結したプレーンテキスト（学習入力用、曲ごとに空行区切り）

## 既知の制約

- 全47曲・合計約8,800文字（トークン数で約6,600）と、小説コーパス（青空文庫想定で数MB）に比べて非常に小さい。43.7Mパラメータのモデルに対して極端にデータが少ないため、学習時にepoch数を増やす、または過学習（＝童謡らしい語彙・言い回しの強い再現）を許容する方向で調整が必要になる見込み。

## ファインチューニング結果（2026-07-31実施）

- `finetune.py` — ベースモデル(`rinna/japanese-gpt2-xsmall`)を上記コーパスでファインチューニングするスクリプト。`ai-tools` conda環境で実行（`pip install accelerate` が必要）。42曲を学習、5曲を検証に分割（`SEED=42`）
- `model-checkpoint/` — 採用したepoch35時点の重み（**gitignore対象**。150MBでGitHubの100MB上限を超えるため、リポジトリには含めない。`finetune.py`＋`corpus.json`から再現可能。トークナイザーはベースモデルと共通なので同梱していない）

### わかったこと

- **検証ロスと「それらしさ」は一致しない**: このデータ規模（学習42曲・検証5曲）では、検証ロスが最小になるepoch5時点ではまだ文体変化がほとんど見えず、逆に検証ロスが上がり続ける「過学習」領域（epoch25〜40）に入って初めて童謡らしい語彙・言い回しが出てきた。150epochまで伸ばして確認したが、検証ロスが後で下がり直す（局所解/double descent的な）現象は起きず、epoch130前後で頭打ちになるだけだった。→ この規模では検証ロスで採用epochを決めるのは無意味で、生成文を実際に聴き比べて選ぶ必要がある
- **epoch数を上げすぎると別の劣化が起きる**: epoch35〜40では単なる暗記が進むだけでなく、「学校 (小5) . . 小4 東(中2)...」のような意味不明な羅列に崩壊するプロンプトが出てきた（epoch27〜30、32で再現、epoch31・35では回避）。一方で「馬にゃんこ」「花にゃっかりだよなあ」のような、支離滅裂だが愛嬌のある崩れ方も同じ高epoch帯で見られ、後者はむしろ採用する方向で判断した（教育展示として「AIが時々ちょっと惚ける」のは許容範囲、という判断）
- **採用: epoch35**。「学校」プロンプトでの崩壊パターンを回避しつつ、童謡らしい語彙と多少の可愛い意味不明さのバランスが良かったため
