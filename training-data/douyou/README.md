# 童謡コーパス（詩スタイル用ファインチューニング素材）

「詩」スタイルのモデルをファインチューニングするための童謡歌詞コーパス。

## 収録作詞者・著作権について

歌詞テキストのみを学習に使うため、著作権の可否は**作詞者の没年**のみで判断（作曲者は無関係）。
2018年の法改正で保護期間は没後70年（2026年時点で1956年以前に没した作詞者が対象）。

| 作詞者 | 没年 | 収録曲数 |
| --- | --- | --- |
| 野口雨情 | 1945年 | 13 |
| 北原白秋 | 1942年 | 23 |
| 高野辰之 | 1947年 | 6 |
| 清水かつら | 1951年 | 5 |

4人とも没後70年超で、いずれもWeb検索で没年を確認済み。

## 出典

歌詞本文は [worldfolksong.com](https://www.worldfolksong.com/songbook/japan/index.html)（世界の民謡・童謡）の各曲個別ページからスクレイピング。
各曲の出典URLは `corpus.json` の `url` フィールドに記録済み。

## ファイル

- `corpus.json` — `{author, title, url, lyrics}` の配列（出典追跡・クレジット表記用）
- `corpus.txt` — 歌詞本文のみを連結したプレーンテキスト（学習入力用、曲ごとに空行区切り）

## 既知の制約

- 全47曲・合計約8,800文字（トークン数で約6,600）と、小説コーパス（青空文庫想定で数MB）に比べて非常に小さい。43.7Mパラメータのモデルに対して極端にデータが少ないため、学習時にepoch数を増やす、または過学習（＝童謡らしい語彙・言い回しの強い再現）を許容する方向で調整が必要になる見込み。

## ファインチューニング結果

### 第1弾（2026-07-31実施、採用epoch35 → 後述の理由で置き換え）

- ベースモデル(`rinna/japanese-gpt2-xsmall`)を上記コーパスでファインチューニング。`ai-tools` conda環境で実行（`pip install accelerate` が必要）。42曲を学習、5曲を検証に分割（`SEED=42`）、**40epochスケジュール**で学習
- **検証ロスと「それらしさ」は一致しない**: このデータ規模（学習42曲・検証5曲）では、検証ロスが最小になるepoch5時点ではまだ文体変化がほとんど見えず、逆に検証ロスが上がり続ける「過学習」領域（epoch25〜40）に入って初めて童謡らしい語彙・言い回しが出てきた。150epochまで伸ばして確認したが、検証ロスが後で下がり直す（局所解/double descent的な）現象は起きず、epoch130前後で頭打ちになるだけだった。→ この規模では検証ロスで採用epochを決めるのは無意味で、生成文を実際に聴き比べて選ぶ必要がある
- **epoch数を上げすぎると別の劣化が起きる**: epoch35〜40では単なる暗記が進むだけでなく、「学校 (小5) . . 小4 東(中2)...」のような意味不明な羅列に崩壊するプロンプトが出てきた（epoch27〜30、32で再現、epoch31・35では回避）。一方で「馬にゃんこ」「花にゃっかりだよなあ」のような、支離滅裂だが愛嬌のある崩れ方も同じ高epoch帯で見られ、後者はむしろ採用する方向で判断した（教育展示として「AIが時々ちょっと惚ける」のは許容範囲、という判断）
- 一旦epoch35を採用したが、「もっと極端に文体が変わってほしい」というフィードバックを受けて第2弾へ

### 第2弾（2026-08-01実施、**採用: epoch60 / 80epochスケジュール**）

`finetune.py`は現在この第2弾の設定（`NUM_EPOCHS=80`）を反映している。

- **重要な発見: 「epoch数」はスケジュール全体の長さに依存する**。学習率は線形減衰でスケジュール終了時に0になるため、同じ「epoch35」でも40epochスケジュールと80epochスケジュールでは実際の重みの動き方（＝その時点での実効学習率）が異なる。第1弾の40epochスケジュール内でepoch数を上げても、epoch35あたりで文体変化と崩壊のトレードオフが頭打ちだった。スケジュール自体を80epochに伸ばしてから同じepoch帯を比較したところ、epoch55〜80あたりで前回のような崩壊（「学校」の番号羅列崩れ）は起きず、「お手々」「出船の仕度」「みんなで歌いきましょうか」のような、より濃い童謡語彙が安定して出るようになった
- 一方で、一部プロンプト（「友達と」「学校」）はepoch55〜80の広い範囲でほぼ同一の文を返す傾向が見られた（多様性がやや乏しくなる副作用）。深刻な破綻ではないため許容
- **採用: epoch60**。童謡らしい語彙の濃さと文法的な一貫性のバランスで選定
- `model-checkpoint/` — 採用したepoch60時点の重み（**gitignore対象**。150MBでGitHubの100MB上限を超えるため、リポジトリには含めない。`finetune.py`＋`corpus.json`から再現可能。トークナイザーはベースモデルと共通なので同梱していない）

### コーパスのクリーニング（2026-08-01追記）

`corpus.json`にスクレイピング由来のノイズが残っていたのを発見・除去して再学習:
- `＜注：...＞`形式の編集注記（すかんぽの咲く頃／ちんちん千鳥、各1箇所）
- 節番号の単独行（落葉松の「一」〜「八」、蛙の夜まわり／俵はごろごろ／さすらいの唄の「１．」〜「４．」等の全角数字）

一方、歌詞本文中の「（）」書きの読み仮名（例:「証城寺の萩（はぎ）」）や、あめんぼの歌のような掛け合い形式の（）書きの応答行は、実際の歌詞内容として残している。

修正後のコーパスで同じepoch60・80epochスケジュールで再学習し直し、`public/models/`のモデルも差し替え済み。
